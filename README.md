# ФотоКвест (photo-quest-ui)

Игра для Учи Мастерской: заврики Гриша и Соня просят ребёнка найти предмет дома, ребёнок его фотографирует, а проверка идёт прямо на устройстве.
Фото никуда не отправляются. Веб, Vite + TypeScript.

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # vitest
npm run build    # tsc + vite build -> dist/
```

Живая камера (рамка вокруг предмета) работает только по HTTPS или на `localhost`.

## Как проверяется фото
1. **Цвета** считаются по пикселям (HSV), модели не нужны.
2. **Предметы** проверяют три сигнала: MobileNet (ImageNet, 1000 классов), COCO-SSD (80 классов, рамки в живой камере) и CLIP (ViT-B/32, сравнение с описаниями всех предметов игры).
3. Если фото почти подошло, задание засчитывается без вопросов.
4. **Живая камера.** CLIP работает в отдельном потоке (`src/vision/clipWorker.ts`) и 1–3 раза в секунду сравнивает кадр с нужным предметом. Когда предмет узнан, прицел и кнопка «Снять» становятся зелёными, а в проверку уходит именно этот кадр: зелёное значит «засчитают». Если предмет не найден, снимается целый кадр без ручной обрезки.

Веса моделей лежат в `public/models/` и грузятся с нашего же сайта. CLIP (~89 МБ) грузится после входа в уровень и необязателен: без него работают MobileNet и COCO.
Файлы CLIP собираются скриптом `scripts/build-clip.mjs` (нужен интернет, предметы берутся из `src/data/clip.ts`). Пакет `@huggingface/transformers` в зависимости не входит, команда установки на время запуска написана в начале скрипта.

## Структура
- `src/data/tasks.ts` — места и задания, цены, соответствие CLIP; `src/data/clip.ts` — предметы для CLIP
- `src/vision/` — проверка фото: `local.ts` (общая), `evaluate.ts`, `clip.ts`, `models.ts`, `color*.ts`, `names.ts`
- `src/camera/` — живая камера, рамка, обрезка
- `src/map/` — изометрия: места (`places.ts`), 3D-предметы (`objects.ts`)
- `public/art/loc/` — спрайты экранов места из Figma (иконки заданий, шапки мест, значки интерфейса)
- `src/main.ts` — экраны и переходы; `src/style.css` — стили
- `src/progress.ts`, `src/storage/` — прогресс (вспышки, найденное); `src/album.ts` — фото-наклейки в браузере
- `src/zavrik.ts` — рост завриков (экран есть, кнопка с главной убрана)
- `src/audio/` — звуки и озвучка (`voice.ts` — записанные реплики из `public/voice/`)
- `docs/voice/` — тексты реплик для озвучки (ElevenLabs)

## Режимы и настройки
- `?debug=1` — панель отладки живой камеры.
- `VITE_PROGRESS_API` — адрес API прогресса (бэкенд `photo-quest-backend`, по умолчанию `/photo_quest/api/v1`; без него прогресс только в браузере). `VITE_DEV_USER_ID` — id ученика для локальной разработки (заголовок `Uchi-User-Id`), в проде его ставит шлюз Учи. Dev-сервер проксирует `/photo_quest/api` на `localhost:8081` (`API_PROXY_TARGET` меняет адрес).

Бэкенд (объяснения Сони через ИИ): `photo-quest-api`.
Лицензии: шрифт Factor A и веса моделей (MobileNet, COCO-SSD, CLIP) — проверить перед публикацией.

## Озвучка (ElevenLabs)

Фразы, задания и английские слова озвучиваются записями из `public/voice`. Если файла нет, говорит голос браузера.
Список записей и сами mp3 создаёт скрипт, ключ в репозиторий не попадает:

```bash
node scripts/build-voice.mjs --dry     # что будет озвучено и сколько знаков (ключ не нужен)
ELEVENLABS_API_KEY=... ELEVENLABS_VOICE_ID=<id голоса Гриши> \
  node scripts/build-voice.mjs         # готовые файлы пропускаются, --force перезаписывает, --only=praise,word- выбирает часть
```

Скрипт обновляет `src/data/voice-manifest.json` (текст -> файл); после запуска закоммитьте `public/voice/*` и манифест.
Нужен Node 22.18 или новее. Всё озвучивает один голос, Гриши (id берётся из библиотеки голосов ElevenLabs): и русские фразы, и английские слова.

## Бусины

Новое найденное задание стоит бусин (цену и баланс отдаёт бэкенд, по умолчанию 2). Бусины платформы хранит кошелёк на сервере, игра только спрашивает:
- `src/api/economy.ts`: баланс, `claimFound` (запись находки на сервере, она же списание), `canAfford`;
- на экране карты показывается баланс (плашка слева от кнопки звука), если оплата включена и баланс известен;
- бусин не хватило: новое задание не открывается («Бусины закончились»), а найденные открываются как обычно; если бусины кончились уже после снимка, находка не засчитывается;
- без адреса API (`VITE_PROGRESS_API`) оплаты нет, всё бесплатно; если сервер недоступен, находка остаётся на устройстве и уходит при следующей синхронизации.

Для локальной проверки: `VITE_DEV_USER_ID` (id ученика) и, при необходимости, `VITE_DEV_ACCOUNT_ID` (аккаунт для бусин, иначе бэкенд берёт его из профиля) в `.env.development`; в бэкенде `BEADS_COST=2` и `BEADS_DEV_BALANCE=6`.
