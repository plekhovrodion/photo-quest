# ФотоКвест (photo-quest-ui)

«ФотоКвест» — веб-игра Учи Мастерской: ребёнок ищет дома цвета и предметы, показывает их в камеру и знакомится с английскими словами. На карте мест живут анимированные питомцы: после выполнения заданий они радуются. Проверка снимка выполняется в браузере; фотографии для распознавания на сервер не отправляются. Прогресс и оплата заданий могут синхронизироваться с бэкендом.

Стек: Vite 6, TypeScript, Vitest. Для запуска нужен Node.js 22.18 или новее.

```bash
npm install
npm run dev      # http://localhost:5173/photo_quest/
npm test         # Vitest
npm run build    # TypeScript + сборка в dist/
```

Камера работает в безопасном контексте: HTTPS или `localhost`. При первом входе показывается видео-знакомство; если браузер запретил автовоспроизведение, появляется кнопка запуска видео.

## Как устроена игра

Сначала доступно место «Цвета». После выполнения всех его заданий открываются остальные места: кухня, комната, школа, ванная, прихожая, еда, двор и лес. В каждом месте есть активный набор заданий из `src/data/tasks.ts`; часть ранее добавленных предметов сейчас скрыта по результатам проверки распознавания.

Камера открывается прямо на экране задания и автоматически делает снимок, когда CLIP устойчиво распознаёт нужный предмет или цвет определяется по пикселям. Распознавание предметов работает в браузере через ONNX Runtime Web. При успехе игра произносит английское слово, предлагает его повторить и затем проводит короткий раунд выбора картинки по услышанному слову.

Найденное задание сразу сохраняется в прогрессе. Фото-наклейка сохраняется только на устройстве; экран альбома сейчас недоступен из игрового интерфейса. На карте показывается прогресс мест и состояние питомцев.

## Распознавание

- Цвета проверяются по пикселям (HSV) и цветовой области в кадре.
- Предметы проверяются MobileCLIP-S0 fp16 в ONNX через ONNX Runtime Web/WASM. Вес изображения — 22,9 МБ; вход — центральный квадрат 256×256 без нормализации, значения RGB в диапазоне 0–1. Цвета проверяются по пикселям.
- CLIP загружается в фоновом режиме при запуске игры; для задания на предмет экран ожидания остаётся до готовности модели.
- Для почти подходящего снимка действует мягкая проверка: игра может засчитать его без повторной попытки.

Воспроизводимый набор Open Images V7 и результаты прежних измерений распознавания описаны в [инструкции по датасету](scripts/eval-datasets/README.md) и [отчёте](docs/open-images-eval.md).

## Структура проекта

- `src/main.ts`, `src/style.css` — экраны, переходы и оформление.
- `src/data/tasks.ts` — активные места и задания.
- `src/camera/` — камера, автоматический снимок и обработка ошибок доступа.
- `src/vision/` — распознавание цветов по пикселям и предметов через CLIP.
- `src/game/`, `src/progress.ts`, `src/storage/` — состояние игры и сохранение прогресса.
- `src/ui/pets.ts`, `public/anim/` — питомцы на карте и в местах.
- `src/audio/`, `public/voice/`, `public/sfx/` — речь, музыка и звуки интерфейса.
- `public/art/loc/` — оформление мест и иконки заданий.

В коде ещё есть старый модуль альбома (`src/album.ts`), но перехода на этот экран в текущем интерфейсе нет.

## API и локальная разработка

`VITE_PROGRESS_API` задаёт адрес API прогресса; в окружении проекта используется `/photo_quest/api/v1`. Без этого адреса прогресс остаётся в браузере и оплата бусинами не включается. Dev-сервер проксирует `/photo_quest/api` на `http://localhost:8081`; адрес можно изменить через `API_PROXY_TARGET`. Бэкенд находится в соседнем репозитории `photo-quest-api`.

Для локальной разработки `VITE_DEV_USER_ID` задаёт ученика (заголовок `Uchi-User-Id`), а `VITE_DEV_ACCOUNT_ID` при необходимости задаёт аккаунт для бусин. В продакшене идентификаторы передаёт шлюз Учи.

`?debug=1` включает диагностическую панель камеры.

## Обратная связь

На карте слева внизу находится кнопка с сердечком. Она открывает общую форму Учи.ру `@uchi/feedback-form` 2.0.8 из «Долой тучи». Компонент и React загружаются при открытии окна. Адрес сервиса задаёт `VITE_FEEDBACK_API_URL`, в production его подставляет Shaman из `FEEDBACK_API_URL`. В сервисе `content_feedback` должна быть настроена анкета `feedback` проекта `photo_quest`. Окно показывает ошибки загрузки и отправки, повтор отправки сохраняет введённый текст. Закрытие доступно кнопкой и клавишей Escape.

## Сборка для Shaman

GitLab-проект фронтенда: `uchiru/product/0-8/content/playground/projects/photo-quest/photo-quest-ui`, ветка `main`. Его pipeline из `.gitlab-ci.yml` собирает образ `photo-quest-ui` и отправляет чарт для приложения `photo-quest-ui` из `.shaman/app.yml`.

Название приложения в namespace не определяет источник чарта. В namespace `vibecoding-basic` приложение `photo-quest-ui` было создано из старого чарта `uchiru/photo-quest/main` с образом `photo-quest`; поэтому кнопка «Задеплоить» открывает старые версии даже после выбора ветки `main`. Для перехода на текущие коммиты нужно в разделе «Чарты» namespace добавить чарт из проекта `photo-quest-ui/main` и проверить на ревью, что образ тоже называется `photo-quest-ui`. Старый чарт следует заменять с учётом уже работающего приложения, а не деплоить рядом вторую копию с тем же именем.

## Бусины

Бусины — серверная оплата новых найденных заданий. Бэкенд сообщает цену и остаток, принимает находку и списывает бусины; повторное выполнение уже найденного задания доступно. Если бусин не хватает, игра показывает модалку «Позови взрослых, чтобы продолжить» по макету Figma. На кнопке всегда написано «Открыть полный доступ». При настроенном пейволе она открывает покупку, при пустом адресе закрывает модалку. Счётчик бусин и отдельная кнопка доступа на карте сейчас скрыты. При запуске с API игра сначала получает `user_id` ученика и выбирает его отдельное локальное сохранение. Если подтвердить ученика не удалось, появляется повтор загрузки. После запуска временный сбой API сохраняет находки на устройстве с последующей синхронизацией. Отказы сервера при синхронизации применяются к локальному прогрессу.

Общее сохранение `photoquest.progress.v2` доступно в автономном режиме. Серверный режим использует ключи `photoquest.progress.v2.user.<id>` и получает существующий прогресс с сервера. Для переноса старого общего сохранения требуется знать его владельца.

При выпуске сначала обновите API с поддержкой `user_id` и `X-PhotoQuest-User-Id`, затем фронтенд.


## Озвучка

Фразы, задания и английские слова звучат из записей в `public/voice/`. Если записи нет, фраза не произносится; голос браузера не используется. Записи и `src/data/voice-manifest.json` создаёт `scripts/build-voice.mjs`; ключ ElevenLabs хранится вне репозитория.

```bash
node scripts/build-voice.mjs --dry
ELEVENLABS_API_KEY=... ELEVENLABS_VOICE_ID=<id> node scripts/build-voice.mjs
```

Перед публикацией нужно проверить лицензии шрифта Factor A и весов CLIP.
