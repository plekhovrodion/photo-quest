# Датасеты для проверки распознавания

Здесь готовится воспроизводимый набор, который проверяет текущие задания игры,
а не произвольный список классов модели.

## Open Images V7

Скрипт читает активные задания из `src/data/tasks.ts`, сопоставляет их с
классами Open Images, выбирает объекты разных размеров и скачивает только
нужные изображения из validation split.

```bash
# Быстрый набор: до 12 примеров на задание
npm run eval:open-images -- --per-class 12

# Основной набор: до 50 примеров на задание
npm run eval:open-images -- --per-class 50

# Только скачать метаданные и показать покрытие классов
npm run eval:open-images -- --metadata-only
```

Результат создаётся в `.eval-data/open-images/`:

- `manifest.jsonl` — одна размеченная пара «кадр × задание» на строку;
- `coverage.json` — найденные и отсутствующие классы;
- `images/` — изображения, общие для нескольких заданий не дублируются;
- `metadata/` — официальные CSV Open Images.

Выбор детерминирован: повторный запуск с теми же параметрами формирует тот же
набор. Приоритет отдаётся крупным объектам (не менее 8% кадра), затем средним
(2–8%) и мелким. Это соответствует сценарию игры, где ребёнок наводит камеру
на предмет.

Open Images содержит неполную разметку. Положительные примеры подходят для
измерения recall. Считать любой другой класс на кадре гарантированно
отсутствующим нельзя, поэтому false positive по этому manifest не измеряется.

Источник: <https://storage.googleapis.com/openimages/web/download_v7.html>.
Лицензию каждого изображения нужно проверять по метаданным Open Images перед
публикацией или распространением кадров.

## Прогон CLIP

CLIP можно измерить напрямую через тот же ONNX-файл, который использует игра:

```bash
python3 -m venv .eval-data/venv
.eval-data/venv/bin/pip install numpy pillow onnxruntime
npm run eval:clip -- --limit 108
npm run eval:clip                 # весь manifest
```

Результат сохраняется в `.eval-data/open-images/clip-report.json`.
