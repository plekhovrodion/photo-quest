# Benchmark распознавания на Open Images V7

Дата базовой линии: 3 ноября 2026 года.

## Набор

- Open Images V7 validation, bounding boxes;
- 587 пар «кадр × активное задание»;
- 513 уникальных изображений;
- 54 из 58 активных заданий сопоставлены с классами Open Images;
- фактические примеры найдены для 52 заданий;
- до 12 примеров на задание, приоритет крупным объектам (≥8% кадра).

Нет box-класса Open Images: глобус, клей, шампунь, зубная паста.
В validation не нашлось подходящих рамок для ластика и расчёски. Для тостера,
ножниц и мыла примеров слишком мало, поэтому их результаты не показательны.

## Модель и метод

- `public/models/clip/vision.onnx`: CLIP ViT-B/32 q8;
- текстовые embeddings из `public/models/clip/text.json`;
- центральный квадрат 224×224 и нормализация как в `src/vision/clip.ts`;
- вероятность softmax с температурой 100;
- порог засчитывания 0,02.

Для каждого примера проверялись два режима:

1. полный кадр Open Images;
2. идеальная вырезка по размеченной рамке с отступом 12%, как при сохранении
   кадра из рамки камеры игры.

## Результат CLIP в ONNX Runtime

| Срез | N | Полный кадр | Вырезанный предмет |
|---|---:|---:|---:|
| Все примеры | 587 | **90,3%** | **95,2%** |
| Крупный объект, ≥8% кадра | 412 | **95,6%** | **97,8%** |
| Средний объект, 2–8% кадра | 171 | **77,2%** | **89,5%** |

Среднее время одного запуска CLIP на CPU этого компьютера — 24–25 мс. Это не
заменяет замер в браузере на телефоне.

## Результат реальной связки игры в Chrome

Весь набор дополнительно прогнан в headless Chrome через те же браузерные
модули, которые использует игра: COCO-SSD `lite_mobilenet_v2`, CLIP и текущие
пороги. Ошибок загрузки или инференса не было.

| Метод | Полный кадр | Вырезанный предмет |
|---|---:|---:|
| COCO-SSD | 60,3% | — |
| CLIP | 89,1% | 95,2% |
| Игра: COCO или CLIP | **92,2%** | **96,6%** |

COCO добавляет 3,1 процентного пункта к CLIP на полном кадре. Наиболее заметно
он дополняет CLIP для плюшевого мишки: 58,3% → 100%, и телевизора: 66,7% →
91,7%. Эти цифры измеряют recall на положительных примерах, а не точность и не
частоту ложных срабатываний.

Проблемные задания с достаточным числом примеров:

| помидор | 12 | 58,3% | 83,3% |
| плюшевый мишка | 12 | 58,3% | 100% |
| телевизор | 12 | 66,7% | 100% |
| уточка | 12 | 75,0% | 66,7% |

Предметы из пользовательской проверки:

|---|---:|---:|---:|
| чайник | 12 | 91,7% | 100% |

В полной логике игры (`COCO OR CLIP`) результаты для этих предметов составили:

фон влияет на embedding полного кадра, а выделение предмета убирает этот сигнал.

## Ограничения

- Open Images не воспроизводит мобильную камеру ребёнка и автокоррекцию цвета.
- Bounding boxes размечены неполно, поэтому этот набор используется для recall,
  но не для достоверного false-positive rate.
- Идеальная вырезка — верхняя граница качества. Камера игры должна сначала
  найти рамку или получить кадр, где ребёнок держит предмет по центру.
- Open Images class `Soap dispenser` сопоставлен заданию «мыло», а
  `Fixed-wing aircraft` — заданию «самолёт»; эти пары требуют ручной проверки.

## Воспроизведение

```bash
npm run eval:open-images -- --per-class 12
python3 -m venv .eval-data/venv
.eval-data/venv/bin/pip install numpy pillow onnxruntime
npm run eval:clip
npm run eval:run
```

Подробные отчёты создаются в `.eval-data/open-images/clip-report.json` и
`.eval-data/open-images/report.json`; они не добавляются в Git.
